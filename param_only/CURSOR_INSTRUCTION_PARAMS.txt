Section 4 only (04_response.md)

When generating or editing only Section 4 (Parameter Configuration Guidelines):

- Use param_only/run/04_prompt.txt as the single source of rules. Follow every rule in it, including "No generic or useless sentences" and "Business-oriented language."
- For each parameter's main explanation, run the self-check: "If I replaced this parameter name with another, would this sentence still be true?" If yes, delete or replace that sentence with function- or parameter-specific content (where the value comes from, when/where in the process it is used, or business meaning).
- Do not use SELECT, DELETE, WHERE, JOIN, or table/field names (e.g. EKKO, EKPO, EKKN) in the narrative unless the guideline cannot be clear without them. Prefer business wording: what the parameter is (company code, vendor, order date) and when/where in the process it is used (order header, schedule line, monitoring window).
- Avoid filler phrases such as "set to focus on," "set to narrow by," "when relevant to the data flow," "when needed," "when applicable." The pipeline verify step will fail if these appear too often.
- After writing 04_response.md, run prompts/PROMPT_Verification_04_Parameter_Configuration_Guidelines.md on 04_response.md and overwrite param_only/run/04_response.md with the corrected output.
